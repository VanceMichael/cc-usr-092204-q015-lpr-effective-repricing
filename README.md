# LPR生效重定价

本项目服务于维护LPR发布、生效区间与贷款合同重定价。仓库保存领域资料、交换契约和可运行的服务入口，便于参与方在同一语义下协作。

## 领域事实

- 一年期与五年期以上LPR分别发布
- 报价由央行授权同业拆借中心公布
- 当前数值在下一次发布前有效
- 报价按有效起止区间引用，发布日期不等于生效日期
- 新报价仅影响满足合同条件的未来区间
- 已入账利息不得被静默重算，更正以冲正与补记留痕
- 一个合同同一时刻只有一条正式还款计划
- 消息重复投递不得重复入账

## 领域模型

| 概念 | 实现 | 要点 |
| --- | --- | --- |
| LPR报价 | `LprRegistry`（`src/publications.js`） | 授权发布来源、期限品种、发布日期、有效起止；窗口随下一期发布闭合 |
| 勘误 | `LprRegistry.publishErrata` | 继承原有效区间，原记录保留，经 `correctedBy` 链关联 |
| 合同条款版本 | `src/contract.js` | 合同基准、加减点、重定价频率；利率转换追加新版本，历史版本不改写 |
| 还款计划版本 | `buildPlan`（`src/plan.js`） | 不可变快照，版本线性递增；每期携带利率形成快照 |
| 还款事件 | 事件日志（`Store.appendEvent`） | 提前还款、利率转换、节假日顺延、冲正均留可解释版本 |
| 入账利息 | `Store` 入账记录 | 写入即冻结；自然键唯一；更正只能冲正+补记 |
| 幂等消息 | `Store.processMessage` | 以 messageId 去重，重复投递返回首次结果 |

## 关键规则

1. **报价引用**：一律按有效区间判定（`lprOn`），发布日期仅为档案信息；窗口重叠直接拒绝。
2. **重定价**：重定价日按合同规则从放款日推导，不随还款日顺延移动；新报价只影响重定价日落在其有效区间内的未入账期次。
3. **计划版本与并发**：所有变更经 `Store.commit` 单点提交，携带期望版本；批量作业与客户变更冲突时重读最新正式计划重试，任何时刻一个合同只有一条正式计划。
4. **入账与冲正**：期次顺序入账、到期后方可入账；入账后期次锁定，重算时原样保留；历史更正以红字冲正+蓝字补记完成，原记录字节级不变。
5. **幂等**：命令信封（`contracts/command.schema.json`）必须携带 messageId；重复投递返回首次结果，入账自然键为第二道防线。
6. **解释与审计**：`rateFormationView` 向客户说明每期利率如何形成；`explainPosting` 从任意入账追到当时有效的LPR、合同条款版本、批准变更与勾稽关系。

## 目录说明

- `contracts/` 保存交换数据的结构约定（领域上下文、报价与勘误、命令信封、利率形成解释）。
- `fixtures/` 提供去标识的领域样例（领域资料、LPR报价、节假日、合同）。
- `src/` 提供领域核心（报价登记、日历、合同条款、计划生成）、账务存储、应用服务与HTTP入口。
- `test/` 核对领域资料载入、各业务不变量、契约校验与服务入口。

## 本地检查

- 运行 `npm test` 检查领域资料、业务不变量与服务入口。
- 运行 `npm start` 启动服务（默认 `http://127.0.0.1:8000`）：
  - `GET /health`、`GET /context`
  - `GET /contracts`、`GET /contracts/{id}/plan`
  - `GET /contracts/{id}/periods/{n}/rate-formation`（客户视角利率形成）
  - `GET /postings/{id}/explanation`（财务与审计追踪）
  - `GET /lpr/{variety}/history`
  - `POST /commands`（命令信封，幂等）

## 设计取舍

- 还款方式为等额本息，月利率=年利率/12，利息四舍五入到分，末期调整尾差；金额以分、利率以基点整数保存。
- 节假日顺延只移动还款日并保留逐日轨迹，不移动合同重定价日。
- 利率转换自未入账期次边界生效；提前还款于还款日办理且到期期次须已入账，剩余本金自该日起重新摊还、期限不变。
- 勘误更正已入账利息时，不追溯调整本金摊还结构，利息差额以冲正+补记入账，后续期次按账面本金重新生成。
